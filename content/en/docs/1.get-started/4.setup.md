The first visit to a fresh instance lands on the setup page. It creates the GitHub App that Knecht signs in with and reads repositories through. This page walks through that flow, then through the settings you need before the first project: who can sign in, the AI provider, and Jira if you use it.

::tip
A community walkthrough of the installation and setup is on [Matthias Andrasch's blog](https://matthias-andrasch.eu/blog/2026/exploring-knecht-cloud-for-ddev-ai-installation-part-1/).
::

## Creating the GitHub App

The setup page has one button, "Create GitHub App". Knecht does not ask for client IDs or secrets. It sends a prefilled manifest to GitHub and gets the credentials back. The app is created under the account that clicks the button, and that account becomes the owner of the instance.

::steps{level="3"}

### Confirm the App on GitHub

GitHub shows the prefilled app with the name `Knecht <your host>`. You can edit the name, everything else is set by the manifest. The app requests write access to contents, pull requests, and issues, read access to metadata, and subscribes to push, pull request, issue, and issue comment events. Submit the form.

### Install the App on Your Repositories

GitHub hands the credentials to Knecht, which stores them encrypted and sends you straight to the installation page. Pick the account or organization, then either all repositories or a selection. The app is public, so it can be installed on any organization you administer, not only on the account that created it. Repositories can be added later in the app's settings on GitHub.

### Sign In

After the installation, GitHub redirects to the login page of your instance. Sign in with GitHub. The same app handles login, so there is no separate OAuth setup. You land in the dashboard as the owner.

::

::note
The setup runs once. When an app exists, the setup page only offers the login. To connect a different app, you would have to reinstall the instance.
::

## Inviting Your Team

Only GitHub accounts on the member list can sign in. Everyone else sees "Access denied" after the GitHub login. The list is under Settings > Access. Enter a GitHub login and click "Invite". The account can sign in right away, its name and avatar show up after the first login.

![The Access page under Settings, with the current members and an invite field for a new GitHub username](/assets/knecht-settings-user.png)

Every member has the same access as the owner, including inviting and removing members. The owner is the account that created the GitHub App and is the only member that cannot be removed.

## Connecting Integrations

Two connections live in the settings and are needed before certain workflow steps work. The AI provider is required for the AI action. Jira is only needed for Jira triggers.

### AI Provider

The AI action runs an agent inside the run's environment, authenticated against one provider with one key. Under Settings > Agent, pick the provider, paste the key, and choose a default model. The key is stored encrypted and is not shown again. Supported providers:

- OpenCode Zen and OpenCode Go, two separate plans with one console key. Pick the plan you pay for, the model lists differ.
- Anthropic, OpenAI, and Google with their own API keys.
- Langdock, a gateway with an EU or US region. The region applies to every request of the instance.

The model list comes from the selected provider. For OpenCode it comes from your workspace, so models disabled there do not show up. The optional subtask model is used when the agent delegates smaller tasks. Each AI step in a workflow can override the default model. The instructions field on the same page is covered on [AI Agent](/docs/usage/agent).

![The Agent page under Settings, with the provider, API key, and default and subtask model fields](/assets/knecht-settings-ai.png)

::tip
Beta testers get OpenCode credit from us. How to get the key and where to paste it is on [Beta Testers](/docs/resources/beta-testers#getting-your-opencode-credit).
::

If the installation preset the key, for example through `KNECHT_AI_KEY`, the field is locked in the dashboard and shows "Preset by the installation".

### Jira (Optional)

Jira triggers watch tickets for a label, a status, or an assignee, and finished runs comment the pull request link back on the ticket. Under Settings > Jira, fill in three fields:

![The Jira page under Settings, connected to a Jira account, with the site URL, email, and API token fields](/assets/knecht-settings-jira.png)

- **Site URL.** The Atlassian site, for example `https://acme.atlassian.net`.
- **Email.** The Atlassian account Knecht acts as.
- **API token.** A token for that account, created under [Atlassian API tokens](https://id.atlassian.com/manage-profile/security/api-tokens).

"Connect" checks the credentials against Jira before anything is stored and shows the account name on success. A dedicated service account, named "Knecht" for example, keeps comments under its own name and limits what Knecht can see to the projects that account has access to. "Disconnect" removes the connection again.
